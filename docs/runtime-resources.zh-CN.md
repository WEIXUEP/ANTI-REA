# Windows 资源加密与缓存案例

[English](runtime-resources.md)

`cases/runtime-resources` 是独立的 C++/CMake 案例，使用 Windows CNG 的
AES-256-GCM，不依赖业务程序或数值库。程序在内存中读取三层文本资源并生成
uint32 数值表，跨进程缓存只保存普通二进制数值，不加载可执行代码。

## 运行原生验收

需要已有 Windows 开发环境、CMake/JOM、Python 依赖及 clang-cl。从仓库根目录运行：

```powershell
python tools/validate_resources_windows.py `
  --llvm-bin F:\Program_Professional\xollvm-windows-llvm23-Release\bin `
  --environment F:\Intel\oneAPI\setvars.bat --jobs 8 --samples 7 `
  --out F:\tmp\resource-acceptance-r001
if ($LASTEXITCODE -ne 0) { throw "Resource acceptance failed" }
```

输出目录必须不存在。也可使用 `--generator Ninja`；不传 `--environment` 时，
从已初始化的 x64 开发终端运行。脚本先复制案例，再修改副本中的资源及密钥，
不删除工作源码。失败运行单独保留。结果以 `result.json` 和 `command-*.log`
为准，不能仅看编译退出码。

## 构建约定

案例默认 `AR_ENCRYPT_RESOURCES=OFF`。OFF 安装 EXE 和明文资源，作为原始泄露
正向对照。ON 必须提供 `AR_RESOURCE_KEY_FILE`，安装包只保留资源消费 EXE，
认证资源包和 AES 密钥嵌入其中。内部 PDB、生成头文件、打包器、私有资源包及
密钥状态文件不安装。

先在 OFF 构建中编译 `resource-packer`，显式运行
`resource-packer.exe keygen <新的私有状态文件>`，再配置 ON。
不复用诊断私钥或名称主密钥。状态文件保存资源密钥、随机 nonce 前缀、递增计数器
和损坏校验值；打包器独占锁定，并在加密前持久化计数器。
状态缺失、损坏、计数耗尽及覆盖生成密钥均报错。活动状态必须与密钥一起保留，
不能回滚或复制为多个独立写入源。
案例限制每个密钥最多加密 2^20 次，每份明文不超过 4 MiB。

资源包的版本、算法、nonce、长度和密钥标识参与认证；解析检查数量、逻辑名称、
顺序、长度及尾部字节。解密资源在内存中消费，不自动回退到源码目录或明文临时文件。

程序支持 `--cache-dir`、`--no-cache`、`--option`，以及显式的明文输入
`--external-dir` 和加密包替换 `--bundle`。必需资源包必须先验证，再使用外部输入
或缓存。案例只支持固定的模型、系数和权重依赖语法，不处理任意源文件包含关系。
默认缓存位置是 `%LOCALAPPDATA%/ANTI-REA/resource-demo/v1`。

## 验收范围

| 检查 | 证据 |
| --- | --- |
| Debug/Release、OFF/ON | 实际运行原生 EXE，用独立 Python uint32 实现核对数值表 |
| AES-GCM | NIST AES-256-GCM 已知向量、往返、错误密钥、AAD、密文和标签篡改拒绝 |
| 清单边界 | 对已正确加密认证但重复、越界、截断、尾随、路径逃逸或包含语法不支持的清单拒绝消费 |
| 缓存边界 | 独立进程、选项失效、禁用及默认目录、损坏修复、ACL 拒写、并发发布和忽略残留临时文件 |
| 构建接入 | 嵌套依赖修改、资源新增/删除/重命名、增量与完整重编译对照、原路径换钥、无变化重建 |
| Nonce 生命周期 | 密钥排他创建、状态校验、计数耗尽拒绝、并发打包 nonce 唯一 |
| 安装包 | 新目录安装及搬迁、原始敏感标签正向命中、保护包与缓存复扫，生成泄露位置 HTML |
| 成本 | 交替记录冷缓存、热缓存及禁用缓存样本，区分程序内部时间和进程墙钟时间 |

缓存身份包括排序后的资源名称和内容、数值选项、指针宽度、消费端源码与编译器指纹
及编译参数。未使用资源也保守计入。随机密文不参与语义身份：换钥后先认证新资源包，
相同数值结果可以继续复用。这是普通数值缓存的策略，不能照搬到具有其他信任要求的
可执行缓存。

## 原生实测

2026-10-22，Windows x64、clang-cl 23.1.2、Intel oneAPI 开发环境下，
`20261022-r004` 运行通过了 Debug/Release 的 OFF/ON 四组，以及换钥后重新安装的
一组；共记录 171 项断言，其中包含重复的数值参考核对，并非 171 个独立场景。
三个指定标签在原始资源中均能检测到，在保护包及已扫描缓存中消失。
保护安装包只有 `bin/resource-demo.exe`。

Release 每种模式采样 7 次，中位耗时如下。程序内部时间包含资源访问、认证和缓存操作；
进程时间还包含启动、退出。这是无预设性能门槛的本机案例观察，不是单独的加密开销测量。

| 模式 | 程序内部时间 | 进程墙钟时间 |
| --- | --- | --- |
| 冷缓存 | 6.53 ms | 14.80 ms |
| 热缓存 | 0.70 ms | 7.37 ms |
| 禁用缓存 | 4.80 ms | 12.98 ms |

冷缓存还需要写入派生表，因此可能比禁用缓存更慢。热缓存结果只证明本案例的复用效果。
现有 Python 测试共运行 114 项，记录 4 处环境相关跳过，其余检查通过；独立原生案例没有跳过检查。
Windows 公共工作流已加入资源案例重跑，其结果与本次本机 LLVM 23 测量分别保存。

## 边界

案例以已知构建密钥的字节串在 EXE 中定位，这属于已知密钥的字节检测，不是盲提取。
也会主动伪造缓存数据并重算普通哈希，
证明这类缓存不能认证恶意写入者。这些反证不会被写成抗逆向或发布者认证通过；
正常可信缓存场景仍必须符合独立数值参考。

保护包中指定资源标签明文消失，但消费端使用的逻辑查找名称仍可能可见。
不宣称隐藏所有字符串、防调试、完整内存擦除、支持压缩、通用依赖解析、
可执行缓存、断电恢复或任意业务程序兼容。

原始验收目录含 AES 密钥、PDB、路径、原文及恶意格式测试包，必须内部保留，
不能发布或放进 skill 下载包。[Skill 英文参考](protection-skill/references/runtime-resources.md)
提供接入指导；下载 ZIP 不包含本原生实现。
