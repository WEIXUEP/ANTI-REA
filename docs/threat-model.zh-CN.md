# 威胁模型

[English](threat-model.md) | 简体中文

## 目标

减少普通字符串搜索、符号检查和程序诊断暴露的信息，同时保留开发者恢复渠道。验收对象是安装后的可执行文件和示例共享库，不是整个开发构建目录。

观察者拥有 EXE/DLL 或 ELF，能运行、搜索字符串、查看导出和反汇编、读取输出。更强的观察者能跟踪执行、修改指令和读内存，这些技术不能阻止此类能力。

## 四种独立机制

1. **密封诊断**：编译前用公钥加密模板，运行时无解密私钥，事件发生时密封动态字段。离线工具使用私钥和发布映射。
2. **不透明标识**：用分域 HMAC 派生 RTTI 和位置 ID，减少语义标签；不使代码和布局成为数学秘密。同密钥的稳定 ID 会泄露相等关系。
3. **发布清理**：通过可见性、导出策略、调试分离、源码元数据处理和 strip 移除执行不需要的信息。
4. **混淆**：xollvm 修改选定表达式、控制流、常量或解释器结构，增加分析工作量，但不是安全边界。运行时解密字符串仍能从内存读取。

## 重要限制

- 公开示例密钥不提供保密性；私钥部署仍无法隐藏算法可观察行为。
- sealed box 提供保密性及密文完整性，不提供发送者认证；持有公钥的人都能产生有效消息。
- 调试器可在字段加密前观察参数。
- 公共 C 导出、标准库导入、加载器名称和公开资源内容仍可识别。
- RTTI 结构、继承、虚表、对象布局、分发和异常机制保留。
- 随意删除公共符号会破坏链接。
- 第三方诊断和运行库断言需按所有权单独处理，本项目不承诺全程序去字符串。
- 删除变量名不使运行值保密。
- 随机字节可能误匹配路径；编码、压缩或拆分文本也可能逃过明文搜索。

不要发布 PDB、私有 IR、映射、密钥或原始调试文件。Windows ACL 和产物存储权限需开发者管理，Python chmod 本身不是 Windows 安全边界。

## 为什么不修改所有二进制字符串

任意链接后替换可能损坏重定位、RTTI、异常记录、长度、校验和及签名，等长替换也不能证明语义安全。示例转换明确的编译器记录，或在目标文件生成前消除敏感输入，再验证行为；不提供通用 EXE 补丁器。
