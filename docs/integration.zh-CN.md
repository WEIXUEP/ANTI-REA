# 构建架构与接入

[English](integration.md) | 简体中文

## 所有权边界

项目独立运行：CMake 管目标配置/安装，Python 管目录生成和 IR 转换，C++ 管运行行为。安装目录仅有运行文件和示例资源，私有映射、密钥、IR、调试文件无安装规则。通用 API 只是演示，不是 ABI 稳定 SDK；接入目标需适配策略，不宜批量替换任意日志调用。

## 编译流水线

```text
C++ 源码 + 已密封目录
 -> Clang 前端：保留原优化意图、禁用 LLVM passes
 -> 按 ABI 替换 RTTI 初始化器
 -> LLVM 校验
 -> 可选 xollvm 混淆及报告校验，仅一次
 -> 移除私有 IR 调试/局部名称元数据、替换 source_filename
 -> 按所需优化级别生成原生对象
 -> 普通链接
 -> 按平台符号策略安装发布副本
```

保留前端优化意图，避免 O2 比较意外含 O0 `noinline`。依赖生成由源码阶段负责，IR 阶段不覆盖依赖记录。支持的调用保留运行库、PIC 和优化设置。

launcher 显式挂到 EXE 和共享库。它不是传递性 CMake 链接需求，链接 interface 库不能自动保护所有消费者 TU。报告按对象路径命名，避免同源文件用于不同目标时碰撞。

解析器支持一个源码和显式对象输出、递归响应文件、引号路径、UTF-16 响应文件、JOM `--`、clang-cl `-TP`；拒绝已知 LTO/PCH/module 模式。它不是通用 Clang 驱动器替代，新模式需验收。与其他 launcher 组合需显式设计调用链。

## 接入既有项目

1. 修改前审计源码和安装产物，区分一方、公共 ABI 和依赖记录。
2. 在拥有配置的 CMake 层增加总开关；依赖支持相同契约时才转发独立 `XXX_CODE_PROTECTION`，不能假设父宏修改依赖二进制。
3. 用中央接口承载机密诊断，保留求值、fatal/throw、级别和路由；动态字符串和异常文本单独检查。
4. 按 ABI 定义内部类型策略，统一规则/密钥重建消费者，验证跨库 RTTI。
5. 审查可见性和公共导出，尽量不把内部 C++ 类型放进公共 ABI；随意改导出会破坏客户。
6. 编译路径、debug、资源、加载路径分别处理，搬迁后验证安装包。
7. 功能保护通过后再选择非热点、充分测试的函数混淆，核对上游报告。
8. 重新审计实际 EXE、DLL/共享库及整包，恢复材料独立归档。

## 兼容性

| 配置 | 契约 |
| --- | --- |
| Linux Clang + 匹配 opt，CPU | 已实现及本地实测 |
| Linux GCC baseline | 普通编译，不是保护 IR 后端 |
| Windows x64 clang-cl + JOM | 有实现和 CI，原生完成范围见验证记录 |
| 普通 MSVC cl.exe | 仅 baseline，保护编译明确失败 |
| LLVM 22/23 + xollvm | 混淆要求，其他主版本不通过能力门槛 |
| LTO/PCH/C++ modules/CUDA/HIP | 教学 launcher 不支持 |
| macOS | 非本项目验收平台 |

## 可复现与发布

比较工具按编译器使用独立构建/安装目录，显式安装前缀，不向系统目录安装 demo。发布源码、文档、脱敏结果和明确公开的示例密钥；`.private`、构建目录、IR、原始报告和 PDB 不入 Git 或安装包。报告本身可能泄露路径/符号，发布前审查。Git ignore 不等于权限控制。
