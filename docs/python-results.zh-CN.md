# Python Windows 实测结果

[English](python-results.md) | 简体中文

2026-10-23 本机验收使用 CPython 3.12.14 x64、PyInstaller 6.22.3、cryptography 50.0.2、
PyArmor 9.2.8 官方试用/core 8.1.2、Nuitka 4.3.1。原生部分使用 clang-cl 23.1.2、Intel
LLD 19.0.0，8 核构建，没有启用 xollvm 混淆。复现见[操作说明](python-protection.zh-CN.md)。

## 保护与恢复效果

六组均通过相同的 265 组行为用例和搬迁检查。敏感词语料只有四个自造标记，不能据此声称
全面无泄露或抵抗恢复。

| 方案 | 原始包直接明文命中 | 实际恢复结果 |
| --- | --- | --- |
| 源码 | 4/4 | 源码直接可读 |
| pyc | 4/4 | 名称、常量、反汇编可读；独立重写通过 265 组用例 |
| PyInstaller onefile | 外层 EXE 0/4 | 提取 CArchive/PYZ 后暴露字节码；分别核对证据后，同一重写实现通过 265 组用例 |
| AES-GCM 加载 | 0/4 | 从发布包携带的密钥解出完整源码，恢复程序通过 265 组；加载期也能捕获源码 |
| PyArmor 官方试用 | 1/4，独立模型资源 | 元数据观察可见原类名和函数名；未验证核心算法恢复 |
| Nuitka standalone | 4/4 | 类名、诊断和资源仍存在；未恢复核心算法 |

独立重写依据发布字节码反汇编和模型 JSON，没有导入或调用原保护算法。同一实现用于 pyc
与 PyInstaller，不是两次独立逆向。分析者知道案例设计；命令只读发布输入不等于盲测。
256 组固定种子随机输入加 9 组边界/错误输入，仅证明已测试域一致。

AES 的错误密钥、头部/tag 篡改、截断均在目标输出前被拒绝。这验证认证行为，不代表
能够向同时持有客户端和密钥的人保密，也不是对 AES-GCM 的密码学破解。

PyArmor 的实验性代码对象序列化触发 `0xc0000005`。失败证据保留，随后仅观察元数据成功。
没有修改运行库或绕过授权，付费模式未测。

REA 的现有 IDA 后端检查了最终 Nuitka EXE：
`3bcd02972d7b65710cf0adc1e62f939265692837b37e5da397aa4c471db5227c`。
确认 `MeridianMixer` 字符串可见，并反编译了 `0x140001000` 的运行时初始化函数，
没有据此声称恢复核心变换。后端函数范围、CFG 和引用能力缺项仍保留，Evidence 已私存，
自有会话已关闭。每方案最多分配 15 分钟，完成表列观察后停止；未完成不代表不可破解。

## 本机性能

每组记录一次首次测量，预热 3 次，再采样 11 次，每进程处理 4096 个整数。以下为毫秒中位值。

| 方案 | 发布包字节 | 构建秒 | 首次记录墙钟 ms | 后续墙钟 ms | 请求内部 ms | 核心变换 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 源码 | 2,530 | 0.004 | 63.527 | 64.193 | 2.464 | 1.190 |
| pyc | 5,941 | 0.014 | 81.829 | 64.642 | 2.840 | 1.154 |
| AES | 4,571 | 0.006 | 112.117 | 116.102 | 1.762 | 1.163 |
| PyInstaller | 8,621,633 | 5.987 | 530.747 | 521.872 | 2.078 | 1.163 |
| PyArmor | 669,615 | 0.255 | 82.059 | 72.584 | 4.913 | 3.534 |
| Nuitka | 13,669,001 | 8.417 | 31.263 | 33.226 | 1.718 | 1.066 |

核心计时不含资源读取和插件；请求内部计时包含两者，但不含启动和 AES 初始解密。
墙钟包含 PyInstaller onefile 解包。原始采样及最小/最大值保留。未清空系统或编译缓存，
未随机轮换方案顺序，不能用此表分离纯加密开销；也没有预先指定业务性能门槛。

发布包大小不等于完整部署成本：源码、pyc、AES、PyArmor 依赖外部 Python，AES 还需要
cryptography；PyInstaller 和 Nuitka 包含运行时组件。构建使用现有编译缓存，不能当作
冷构建性能。小案例结果不外推到业务程序。

## 证据与失败记录

私有证据保留在 `F:/tmp/anti-rea-python`：

- r001：clang-cl 编译成功，缺少 lld-link 导致链接失败。
- r002：六组行为验证成功，PyArmor 序列化观察崩溃。
- r003/r004：受限观察与初次独立恢复验真。
- r005：最终核心计时、六组各 265 组行为、四种 AES 拒绝场景和三组恢复验真；最终扫描版本位于 `analysis-complete`，旧分析版本保留。

独立检测工具还验证了路径穿越、重名、符号链接拒绝、解压限制、pyc 不执行、magic 不匹配、
baseline 不匹配、报告转义和运行观察显式开启。报告、代码捕获、私有用例、密钥及解密结果均不入 Git
或 skill 下载包。Windows 验收来自本机，仓库原有 Windows 工作流手动禁用状态未改动。
