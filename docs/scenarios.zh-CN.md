# 泄露场景与缓解

[English](scenarios.md) | 简体中文

在仓库根目录用 baseline 和 protected 构建同一源码。以下是通道检查实验，不代表整个程序已不可读。

| ID | 触发或检查 | 基线暴露 | 保护行为 |
| --- | --- | --- | --- |
| D01 | `anti-rea-demo verify` | 条件、路径、行、签名、网格诊断 | 公开级别、不透明位置、密封事件；仍 abort |
| D02 | `anti-rea-demo assert` | 内部不变量及位置 | 保留致命行为，移除描述明文 |
| D03 | `anti-rea-demo warning` | 预条件器细节和迭代数 | 模板与字段加密，可离线恢复 |
| D04 | `anti-rea-demo exception` | 诊断及 `what()` 中的内部错误 | 密封事件和不透明异常文本；退出仍为 3 |
| R01 | `anti-rea-demo rtti` | 内部类、模板、lambda/函数名 | 替换名称，保留 RTTI 功能 |
| S01 | 库符号审计 | 内部全局变量和方法名 | 隐藏定义，剥离安装后的 ELF |
| S02 | 导入导出审计 | 公共 `ar_*` API 和运行依赖 | 必需 API 有意保留 |
| P01 | `anti-rea-demo location` | `__FILE__` 和签名 | 不透明文件 ID |
| P02 | 调试元数据 | 源码名、路径、变量、编译器信息 | 私有 IR 保留，保护对象不含私有源码元数据 |
| P03 | `anti-rea-demo resource` | 描述性资源名 | 稳定别名和可执行文件相对定位 |
| P04 | ELF 运行路径 | 构建目录 RUNPATH | 安装版使用 `$ORIGIN`，验证搬迁 |
| P05 | Windows CodeView | 可能的完整 PDB 路径 | 仅记录 PDB basename，PDB 保持私有 |
| O01 | `policy_dispatch` | 普通分支和常量 | 按等级选择表达式/CFG 变换 |
| O02 | mixed-vm 的 `policy_token` | 直接算术 | 使用 VM，与 flattening 分离 |
| O03 | 普通分发文本 | 诊断目录之外的明文 | protected 保留；xollvm strenc 隐藏静态表示 |

## D01–D04：诊断也是数据

断言不只泄露消息：字符串化表达式暴露变量名，`__FILE__` 暴露路径，签名宏暴露模板和内部类型。只在运行时改文本可能仍把原文留在只读数据段。

保护头文件只包含公开级别、ID、公钥和加密模板。条件照常执行，保护预处理分支不展开原始表达式文本和位置。成功路径仅求值条件一次，不格式化失败参数；失败仍 abort。示例 `AR_ASSERT` 始终启用，不等同于受 NDEBUG 控制的标准 `assert`。

异常同时保护报告与 `what()`；仅保护 logger 而抛出原始消息仍会泄露。标准库通用消息可能保留。

## R01：RTTI 不只是符号表

strip 后仍可能有运行时使用的类型名。`-fno-rtti` 改变 C++ 功能，不是等价保护。示例在代码生成前替换选定 RTTI 字符串初始化器，保留 typeinfo、指针、虚表及继承数据。

测试覆盖虚继承、多继承、跨库工厂、兄弟转换、`typeid` 比较和 DLL 抛出/EXE 捕获异常；内部类型模板、局部 lambda 和带引号 LLVM 名称也被覆盖。

策略仅选择 `aegis::internal` 及 `print_rtti` 局部类型，不是通用 ABI 转换规范。所有生产者/消费者需统一规则和密钥。不要将 `type_info::name()`、排序或哈希持久化为公共序列化格式。

## S01–S02：符号所有权不同

发布副本可删除本地符号，动态导入导出可能为加载、插件和 ABI 必需。示例保留小型公共 C 接口和标准运行依赖，不把内部 C++ 类作为插件 API。

strip 不会清除诊断、RTTI 初始化字符串或运行时路径。应比较 stripped 与 protected。局部变量名通常来自调试记录，扫描器不会由寄存器/栈使用推断原名。

## P01–P05：各路径通道分开处理

编译器前缀映射不处理任意字面量；LLVM debug 元数据和 `source_filename` 是另外的通道。安装 ELF 使用相对加载路径，Windows 使用 PDB basename 规则而不是 ELF strip。资源根据可执行文件定位，改名仍可搬迁。

资源是无害系数，不是 JIT 源码；真实 JIT 源码即使改名仍暴露内容。构建目录、启动日志和映射保持私有，可包含发布版刻意移除的信息。

## O01–O03：验证实际变换

编译成功不证明 pass 执行。VM 尤其可能跳过异常处理代码；选定策略函数避免这些结构。launcher 校验逐函数报告，所需变换缺失或跳过即失败，VM 与 flattening 目标分离。

普通分发字符串展示诊断保护不是全程序加密。strenc 在进程初始化时解密，不能提供私钥不在程序内的公钥诊断保密性。
